## Data Configuration

Default datatable: `main`. This app is public with a server-checked daily access code on all five backend runnables, and uses sandbox isolation. The code is the current Asia/Kolkata date in DDMMYYYY format, evaluated on every request. Preserve this policy when deploying; never remove a backend access check.

### Whitelisted Tables

Whitelisted tables: `main/sales_intelligence_groups`, `main/sales_intelligence_health`, `main/sales_readiness_deals`, `main/sales_intelligence_budget`, and `main/sales_intelligence_profiles`. Do not query or alter unrelated tables, scripts, flows or schedules.

Deploy this app only with `local/lead_pipeline/deploy_dashboard.ts` after reviewing changes. It asserts app ID 21/path, preserves policy and server-compiles this app. The globally installed 1.679.0 CLI mishandles raw-app helper/migration paths; do not use broad sync. `./wmill` is generated by Windmill's bundler; do not replace it with an assumed window global.

### Adding a Table

Edit `raw_app.yaml`:

```yaml
data:
  datatable: main
  tables:
    # Add tables here
    - main/new_table  # ← Add like this
```

**Table reference formats:**
- `<datatable>/<table>` - Table in public schema
- `<datatable>/<schema>:<table>` - Table in specific schema

## Quick Reference

**Backend runnable:** Add `backend/<name>.ts` (or .py, etc.), then run `wmill generate-metadata`

**Call from frontend:**
```typescript
import { backend } from './wmill';
const result = await backend.<name>({ arg: 'value' });
```

**Query datatable (TypeScript):**
```typescript
const sql = wmill.datatable();
const rows = await sql`SELECT * FROM table WHERE id = ${id}`.fetch();
```

**SQL migrations:** Add `.sql` files to `sql_to_apply/`, run `wmill app dev`, then whitelist tables
