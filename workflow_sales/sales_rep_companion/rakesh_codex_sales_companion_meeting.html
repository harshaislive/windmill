Before We Open Codex

The argument: sales work has become too context-heavy for memory alone.

A good sales rep is not short of effort. The hard part is carrying live CRM state, customer intent, WhatsApp history, email threads, Typeform answers, GIS flow, next activities, and follow-up timing at the same time.

The human limit

One person cannot perfectly remember every open loop, objection, message, and CRM hygiene step while also selling well.

The CRM limit

CRM stores truth, but it does not think across the full context or turn rough work into next action by itself.

The Codex layer

Codex reads the operating surface, reasons across it, drafts the next move, and keeps learning in files, logs, rules, and deal folders.

Give Rakesh a second brain that is grounded in CRM truth.
Opening Frame

Not ChatGPT brainstorming. Not manual CRM burden.

ChatGPT

Good for ideas and copy, but it does not know live deal state unless someone copies context every time.

Manual CRM

Clean in theory, but hard for one rep across calls, WhatsApp, email, no-shows, notes, and activities.

Codex Companion

Reads real context, checks gaps, drafts next steps, writes only after approval, and improves through a project memory system.

What makes it more than chat

  • AGENTS.md tells Codex the operating rules.
  • Deal folders preserve research, drafts, notes, and evidence.
  • Decision logs record what should change future behavior.
  • Incidents and learnings prevent repeated mistakes.

What Rakesh gets

  • Faster prep before calls.
  • Cleaner CRM notes and activities.
  • Sharper follow-up timing.
  • Less leakage across GIS, no-shows, WhatsApp, email, and activities.

Codex is an intelligent extension of the rep. It connects CRM history, customer intent, sales process, automation state, communication tone, project files, and learned rules faster than one person can manually hold in working memory.

The One Rule

CRM stays the source of truth.

CRMOfficial deal state, people, activities, notes, owner, stage, label, communication history.
CodexReasoning workbench: reads, summarizes, drafts, checks, proposes, writes after approval.
Deal FolderWorking file cabinet: research, drafts, snapshots, call notes, evidence.
Repo LearningReusable memory: decisions, incidents, patterns, learnings.

Hands-On 2

Prep and enrich one deal before a call.

Prep and enrich Pipedrive deal <deal_id>. Read CRM first. Summarize the lead, last touch, route, risk, and best next action. If useful, research public/company/context signals. Separate verified CRM facts from enrichment notes. Do not write anything.
Check owner, collective, stage, label, and latest activity.
Find last WhatsApp, email, Typeform, GIS, webinar, or 1on1 context.
Enrich only where useful: public/company context, affordability signals, decision-maker cues, or questions to verify.
Give Rakesh the call agenda and likely objections.
Suggest the next action, but do not change CRM yet.

Research can sharpen the call, but CRM stays the source of truth. If enrichment changes selling context, Codex should propose a CRM note and ask before writing it.

Project Structure

Each serious deal can have a folder.

The folder is a file cabinet, not the CRM.

data/tracking/sales_deals/ pipedrive_14049_customer_name/ README.md snapshots/ research/ drafts/ call_notes/ sent_messages/ attachments/ decisions.md next_actions.md
This convention should live in AGENTS.md or a linked rule doc: When creating a deal folder, use data/tracking/sales_deals/. Use the CRM ID first in the folder name. Add a README with CRM link, owner, collective, last refreshed date, and a warning that CRM is source of truth.
Codex Basics

Projects hold the system. Threads hold the work.

Project

The workspace where tools, files, instructions, and integrations live.

Thread

One conversation or work session. Keep deal work in one thread while context is active.

Good thread names: Daily Sales Queue - 2026-06-23 Deal 14049 Prep And Follow-Up No-Show Recovery Review GIS Opened Follow-Up Batch Email Tool Setup With BI
