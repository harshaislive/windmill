What sales should know

Owner routing is automatic from the collective selected in the Typeform. A Mumbai or Bhopal lead should land with Vivekanand. A Hammiyala or Poomaale lead should land with Sai Rakesh.

Important subtlety

Bhopal/Mumbai brochure leads book directly in Vivek's Calendly. Windmill polls four times daily and writes only confident matches to Pipedrive. Hammiyala/Poomaale keep the Rakesh second-Typeform path.

Lead clicks Reschedule Call

  1. Windmill finds the existing calendar event.
  2. Calendar event is cancelled.
  3. Meeting fields are cleared.
  4. Deal moves to 1on1 Awaiting.
  5. Lead receives owner booking link.

Lead clicks Confirm Attendance

  1. Deal moves into 1on1 Pending.
  2. Lead gets a short confirmation WhatsApp.
  3. Reminder and owner-check loops can pick it up.

WhatsApp delivery failed

  1. Status events never trigger reschedule.
  2. Failure creates open task WhatsApp failed to deliver.
  3. Error code and reason are shown for sales/admin.

Why this matters

Interakt sends both user actions and delivery status updates. Status events may contain the words Reschedule Call inside the template body, but Windmill now ignores those as actions unless they are actual button replies.

Sales view

Look for simple activity subjects: Booking link sent on WhatsApp, Attendance confirmed on WhatsApp, WhatsApp failed to deliver.

How the webinar access link is fetched

04C registers the invitee into the matched Zoom webinar and writes the registrant join URL into the Pipedrive Meeting URL field. 08A fetches that field first; if it is missing, it falls back to the webinar activity note and extracts the first URL.

Reminder send contract

08A reads the deal's owner-owned Collective Webinar activity, calculates the due reminder window, sends the approved Interakt template, and passes the Zoom access link as a body value. If Interakt or the phone/link check fails, it creates an open manual WhatsApp task instead of silently dropping the lead.

Current behavior

After a webinar booking, 04C also asks the attendance worker to schedule Zoom attendance checks. The fallback 13B schedule checks recent completed webinars every 3 hours and can schedule the post-webinar 1-on-1 prebook path.

Guardrail

The attendance worker stores scheduled meeting/deal IDs in state, so the one-off path and fallback schedule are intended safety nets, not two independent sales journeys. Still, duplicate jobs should be checked before manual reruns.

Owner marked attendedOwner confirmed attendance from WhatsApp.

Golden rule

Pipedrive should answer: what happened, what the lead received, what the owner needs to do, and what the next automation is waiting on.

When unsure

Look at the latest open activity first. Open activities usually mean a human needs to act. Done activities usually explain what the system already did.

11 / Known Duplicates, Loopholes, And Checks

These are the places to inspect before manual reruns or cleanup.
Public Typeform, Pipedrive, Calendly routesThese HTTP triggers still use no Windmill auth. They rely on guarded payload logic. Interakt inbound is signed.
Calendly old n8n webhooksOlder docs flagged active n8n user-scope webhooks. Recheck Calendly before deleting or assuming Windmill is the only consumer.
08Z reminder pollerThe fallback webinar reminder schedule still exists but is disabled. Do not enable unless one-off reminder jobs are not being scheduled.
Zoom registrant import vs Calendly worker09B is not attendance; it imports future Zoom registrants into Pipedrive. Review only same-person same-collective CRM duplicates before merge/rerun.
Attendance one-off plus fallback04C schedules attendance checks and 13B also reconciles recent webinars. State should prevent repeat work; verify queued jobs before manual reruns.
